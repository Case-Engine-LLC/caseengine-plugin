# Step 08 - Quality Assurance

> **Exec:** deterministic gates, plus one LLM pass (the Anti-AI two-pass scan)
> **Assets:** `references/document-structure.md`, `references/placeholders.md`, `references/editorial-rules.md`, `references/statics.json`, `references/cover-spec.json`

## What

The only step that gates the document as a whole. Section steps gate themselves; everything cross-cutting is checked here, once, before anything reaches Drive. Good output is a clean pass on every gate below, or a named failure with the repair applied and the whole set re-run.

Almost every gate is mechanical - grep-able or countable. The v1 format failed QA on things nobody could check ("sounds choppy", "too much jargon"), so a vague gate is not a gate. If a new failure mode appears that no gate catches, add the gate before shipping the fix.

**One gate is deliberately not mechanical: the read-through in tier 4.** It exists because on 2026-08-18 a generated outro line passed every mechanical gate and was still unreadable: "That is a lot of detail on what a car accident case is actually worth that people usually have to piece together on their own." Correct tokens, correct counts, no banned words, no jargon, no em dash. It is simply not a sentence anybody would say. No grep catches that, and this document is spoken aloud, so the cost of shipping one is a host stumbling on mic. The read-through is judgment, but its criteria are concrete and listed, which is what separates it from "sounds choppy".

## Inputs

- `artifacts` - from `steps/07-render.md`.
- The reference files in the Assets line - each gate checks against its own source of truth, never against a copy.

## Procedure

Run all five tiers in order. A failure repairs in place and re-runs the full set - not just the failed gate.

1. **Structural gates** [deterministic]
   - **Placeholders** - a grep for `{{...}}` returns only the eleven approved tokens in `references/placeholders.md`. Zero invented tokens, zero `{{REGION}}`, zero `{{CITY_2}}`. Every token renders bold.
   - **Statics verbatim** - the active welcome constant renders byte-identical. It is ONE of the four in `references/statics.json` -> strings: standard or embedded-name variant, episode 1 or not (Gabe 2026-08-26). An embedded-name show never renders "with **{{ATTORNEY_NAME}}**" - it doubles the name. Nothing substitutes into any of them; `{topic_phrase}` left `welcome` on 2026-08-18. Compare against the constant, not by eye.
   - **Generated-field allowlist** - the only per-episode generated content is `topic_phrase`, `setup`, `credential`, `prompt`, the attribute bullets, the Short-Form question sets with their bullets, and the outro's three spoken lines. `cold_open` is a deprecated alias for `setup`; `need_to_know` and `examples` are retired with the Internal Notes block. Anything else differing from the constants is drift.
   - **Document structure** - section order matches the locked shape exactly. Downstream Client ROS reads this shape to populate.
   - **Retired sections stay retired** - zero occurrences of the cut sections listed in `references/document-structure.md`.
   - **Topic Plan reconciliation** - the live Google Doc Topic Plan was fetched this run and `topic_plan_doc_id`, `topic_plan_revision_id` and `topic_plan_fetched_at` are recorded. Every S2 question resolves to a live Doc row via `topic_plan_ref`, in the Doc's relative order, with tail truncation allowed and reordering forbidden. Zero questions from struck or vetoed text, zero carrying an unresolved comment. Gates TP-1 to TP-6 in `references/short-form.md`. Never trust a local `topic-plan-v{n}` mirror - clients edit the Doc by hand and the mirror does not know.
   - **Cover page** - per the gates in `references/cover-spec.json`, including the logo inline object.
   - **Page breaks** - the cover, S1 and the appendix each start on a new page. S2 does NOT: it flows on from the S1 outro behind a horizontal rule, changed 2026-08-18. No section carries an inherited break it did not ask for.
   - **Heading colors** - H1 section headers CE Blue; H2 CE Dark. A blue H2 means the renderer regressed.

2. **Content gates** [deterministic]
   - **Introduction** - four lines plus the beat direction in order (STATIC welcome, generated setup, generated credential as its own paragraph, generated prompt), line 1 byte-identical to the constant, line 2 pattern-matched and carrying `{{STATE}}` with any number traced to a source in metadata, exactly one credential frame in line 3, line 4 ending in a question mark with at most two asks, and 80 to 110 words. Gates IN-1 to IN-8 in `references/introduction.md`.
   - **Single prompt** - the Introduction contains exactly ONE bolded prompt paragraph, line 4. A second is the single most likely regression in this format and it FAILS. The credential in line 3 is not bold in full; only its placeholders carry bold.
   - **Speaker tags** - `ATTORNEY RESPONSE` in the Introduction is the only one in the document. Zero `INTERVIEWER` tags: the tag was cut from both the Introduction and the Outro on 2026-08-18 (OC-1).
   - **Attribute block** - ten to twelve bullets, each a bold lead-in plus one sentence of what to cover, zero question marks anywhere in the block, ordered credentials through logistics. No `Attributes to Hit` heading. Gates AT-1 to AT-8 in `references/attributes.md`; AT-1 and AT-2 are enforced mechanically by `scripts/build-ros-template-v2-docx.py`.
   - **Short-Form count and bullets** - exactly ten questions per location, `**Q1:**` through `**Q10:**`, every location the same count; each question fully bold including its label; two to four bullets under each in `[{Label}]{.underline}: {detail}` form with labels underlined and never bold; nothing else under a question. Gates SF-1 to SF-4.
   - **Outro** - three generated spoken lines in the order thanks, sign-off, reach-out, with the sign-off deliberately not last, `{{STATE}}` and never `{{CITY}}` in line 3, and zero occurrences of "Case Engine". `outro_note` byte-identical. Gates OC-1 to OC-9 in `references/outro.md`.
   - **Geo distribution** (reads the JSON, not the Doc) - every question carries exactly one `geo_tag` from {CITY, CITY + REGION, REGION, NEUTRAL, STATE}, with exactly three CITY-tagged per location. The `pod-2B` city-share ceiling is NOT applied (SF-5).
   - **Jargon scan** - zero statute numbers, case citations, rule names, or legal element names anywhere ABOVE the appendix heading. No exempt section. The appendix is scoped out because it carries n-gram rows verbatim; never edit a bank row to make the scan pass.
   - **Guest framing** - case-insensitive grep for `my guest|our guest|today'?s guest|joining us|thanks for coming on` returns zero. The attorney owns the show.
   - **Tokenization integrity** - zero hard-coded firm, attorney, city, or state names. The region is the sole intentional plain-text exception.
   - **Appendix completeness** - row count equals the n-gram table row count exactly.
   - **Question sourcing** - every short-form question traces to n-gram substance via `source_ngram_ref` or to the attribute set. An untraceable question is an invented one.
   - **No em dashes** - plain hyphens only.
   - **No leaked markup** - zero `{.underline}`, `<u>`, or literal `**` visible as text.

3. **Anti-AI Detection two-pass scan** [LLM - 1 call] - the full Section 7 audit at the [canonical doc](https://docs.google.com/document/d/1hp7bxOFRlMhCuhjHNY0j05JrB97-KOFD0XUCQM3gMBU/edit). Pass 1 mechanical: em dashes, banned vocabulary, banned phrases, triadic rhythms, summary-only closers, date formatting, no emojis. Pass 2 skeptical re-read from the top: did I actually check every line or skim? One pass is not enough.
   - **v2-specific spoken check** - this format is read aloud more than any other CE deliverable. Read the welcome, the prompt, and three short-form questions out loud. Anything that only works on the page fails.

4. **Read-through** [LLM - 1 call, HARD, runs LAST of the content tiers] - read the ENTIRE document top to bottom, in order, as one continuous piece, and read every spoken line ALOUD. Not section by section, not the diff, not the parts that changed. The whole thing, in the order a listener hears it. Mechanical gates check lines in isolation; this is the only gate that sees the document as a document.
   - **Grammar and sense.** Every sentence parses on the first pass. Flag anything you had to re-read: a clause hanging off a noun phrase, a relative pronoun whose antecedent is ambiguous, a main verb more than roughly eight words from its subject, a stranded tail after a long sentence.
   - **Says it like a person.** Two short sentences beat one long one. If a line would be strange to say out loud to somebody standing in front of you, it fails, regardless of how well it reads on the page. This is the "sounds normal" north star from `references/introduction.md`.
   - **Cross-section repetition.** The intro and the outro are generated separately and neither can see the other. Check that they do not reuse the same phrase, the same credit, the same stakes clause, or the same verb. Same for the short-form questions against each other and against S1.
   - **Continuity.** The prompt in the Introduction and the questions in S2 are about the same episode. Names, framing and tense agree across sections.
   - **Nothing orphaned.** No line refers to a section that was cut, no pronoun points at something removed, no direction line survives from a retired block.
   - **Output is a list of flagged lines with the rewrite applied,** not a pass/fail opinion. A read-through that returns "reads fine" without quoting anything it checked did not happen; re-run it.

5. **Artifact gates** [deterministic] - payload validates against the schema; metadata carries the full provenance block; markdown, payload, and metadata all written; no write path collides with a legacy artifact name; destination is inside the template library.

## Outputs

```
qa: {
  passed: bool,
  gates_run: int, gates_failed: [str],
  jargon_scan: "PASS"|"FAIL",
  read_through: {flagged: [str], rewritten: [str]},
  repairs_applied: [str]
}
```

## Validation

Every gate above returns clean. QA does not pass "with notes" - a note is a failure that has not been repaired yet.

## Failure modes

| Failure | Exit behavior | Routes to |
|---|---|---|
| Any structural or content gate fails | Repair in place, regenerate the payload and metadata, rebuild, re-run the FULL set | the owning section step |
| Anti-AI scan hits on pass 2 | Fix and re-run pass 2 until clean | this step |
| Read-through flags a line | Rewrite it in place, then re-run the full set - a rewrite can break a mechanical gate | the owning section step |
| Read-through returns clean without quoting anything | It was skipped. Re-run it and require quoted lines | this step |
| Schema file absent | Log `schema_status: missing`, continue | continue |
| Gate disagrees with a reference file | The reference file wins; a gate is a check, never a second source of truth | this step |

## Where the S1 and S2 gates live

They are itemized in tier 2 above, added 2026-08-18 when `steps/04-segment-1.md` and `steps/05-segment-2.md` locked. The reference file owns the gate's definition and this step owns the check - a gate here is never a second source of truth, so when a gate and its reference file disagree, the reference file wins and the gate is the thing to fix.
